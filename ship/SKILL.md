# 올리기 — 커밋 · 푸시 · PR

**약속 셋:** ① 시킨 만큼만 한다(커밋 / 푸시 / PR). ② 기본 브랜치(main)에 직접 올리지 않고, 강제 푸시하지 않는다. ③ 확인한 것만 "확인함"이라고 쓴다.

## 0. 무엇을 시켰나

| 말 | 하는 일 |
|---|---|
| "커밋해" | 1 → 2 → 3 → 4까지. 푸시는 묻는다 |
| "커밋하고 푸시해" | 1 ~ 5 |
| "PR 올려" · "커밋하고 PR 올려" | 1 ~ 7 |
| "깃 최신화해" | 원격을 받아 온다(8). 지금 브랜치의 PR이 병합됐으면 기본 브랜치로 옮겨 받는다 |

프로젝트에 규칙 문서(CLAUDE.md · CONTRIBUTING · git 규칙)가 있으면 **그것이 먼저다** — 커밋 제목 모양, 작성자 메일, 버전 기록 방식, 브랜치 이름.

## 1. 지금 상태를 본다

- `git status`로 고친 파일 목록, 지금 브랜치를 본다.
- **기본 브랜치 위면** 새 브랜치를 먼저 판다(최신 원격 기본 브랜치에서).
- **이 브랜치의 PR이 이미 병합됐으면**(`gh pr list --head <브랜치> --state all`) 여기에 더 올리지 않는다 — 병합된 PR에는 따라가지 않는다. 최신 기본 브랜치에서 새 브랜치를 따고, 아직 올라가지 않은 커밋을 옮긴다(`git cherry-pick`). 그사이 지워진 파일(버전 기록 조각 등)은 새 이름으로 다시 만든다.

## 2. 시험을 돌린다

- 프로젝트의 검사 명령(전체 시험 · 린트 · 링크 검사)을 **실제로 돌리고** 결과 숫자를 적어 둔다(언제 쟀는지와 함께).
- 실제 브라우저로 누르는 시험(e2e)이 도구가 없어 건너뛰어지면, 그 사실을 적고 가능하면 따로 돌린다.
- 실패가 이번 변경 때문인지 모르면 바꾸기 전 코드로 같은 시험을 돌려 가린다. 원래부터 실패하던 것은 이름과 이유를 PR에 적는다.
- 실패한 채로 커밋하지 않는다(원래부터 실패하던 것은 예외 — 그렇다고 적는다).

## 3. 변경 기록을 맞춘다

- 프로젝트가 정한 기록이 있으면 같이 넣는다 — 버전 기록 조각, 고칠 목록, CHANGELOG 등. 없으면 건너뛴다.
- 화면 · 동작을 바꿨으면 그 기록의 "종류"를 맞게 고른다(기능 변경 vs 작은 고침).

## 4. 고친 파일만 골라 커밋한다

- `git add -A` · `git add .`를 쓰지 않는다. **이번 일로 고친 파일만** 이름으로 넣는다. 모르는 파일이 섞여 있으면 묻는다.
- 비밀값(키 · 토큰 · 비밀번호 · `.env`)이 들어가지 않았는지 본다.
- 커밋 메시지: 제목은 프로젝트 모양(없으면 `타입(범위): 설명`), 본문에 **무엇을 왜** 한두 줄, 시험을 어떻게 맞췄는지. 작성자 메일은 사람이 정한 주소(공개 저장소면 noreply). 세션이 정한 공동 작성 줄로 끝낸다.
- 훅(커밋 전 검사)이 막으면 까닭을 고친다. **훅을 피하지 않는다**(`--no-verify` 금지).

## 5. 푸시한다

- 브랜치로만 푸시한다. 기본 브랜치 · `--force`는 하지 않는다.
- 훅이 푸시를 막으면 우회하지 않고 까닭을 말한다. 필요하면 사람이 자기 터미널에서 할 명령을 한 줄로 준다.

## 6. PR을 연다

- 제목: 커밋 제목과 같은 모양. 이슈 키가 있으면 넣는다.
- 본문(프로젝트 PR 틀이 있으면 그 칸대로):
  - **무엇을 바꿨나** — 사람이 정한 결정, 같이 정리한 것, 그대로 둔 것
  - **확인** — 돌린 시험과 숫자 · 날짜, 화면을 봤으면 무엇을 봤는지
  - **확인 못 함** — 보지 못한 화면 · 상태 · 기기
  - **알림** — 다른 사람이 맡은 폴더 · 파일을 고쳤으면 그 사실
- 병합은 사람이 한다(Claude는 병합하지 않는다).

## 7. 열고 나서 본다

- `gh pr view <번호> --json mergeable`로 부딪침이 없는지 본다(UNKNOWN이면 잠시 뒤 다시).
- **부딪치면(CONFLICTING):** 최신 기본 브랜치를 이 브랜치에 합친다(`git merge origin/main`). 부딪친 곳은 **양쪽을 살려** 푼다 — 남의 새 내용을 지우지 않는다. 다시 시험을 돌리고, 남의 시험을 맞춰 고쳤으면 PR 코멘트로 알린다. 푸시는 시킨 경우에만.

## 8. 깃 최신화

- `git fetch` 후 새로 들어온 커밋을 한 줄씩 보인다(누가 · 무엇).
- 지금 브랜치의 PR이 병합됐으면 기본 브랜치로 옮겨 `pull --ff-only`. 아직 열린 PR이면 부딪침 여부를 알려 준다.
- 고쳤는데 커밋하지 않은 파일이 있으면 건드리지 않고 알린다.

## 하지 않는 것

- `git reset --hard` · `git clean -f` · `git checkout -- <파일>` · `git restore`로 남의 · 내 수정을 날리는 것. 되돌릴 일이 있으면 먼저 묻는다.
- 병합된 PR의 브랜치에 커밋을 더 올리는 것, 저장소 · 브랜치 지우기(묻고 나서만).

## 보고

PR 링크 · 커밋 짧은 번호 · 넣은 파일 수, 시험 결과(날짜), 확인 못 한 것, 사람이 할 일(병합). 짧게.
