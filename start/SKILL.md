# 시작하기 — 새 작업, 새 브랜치

**짝:** 끝낼 때는 `ship`(커밋 · 푸시 · PR), 시작할 때는 이 스킬. 한 작업 = 한 브랜치 = 한 PR.

**약속 셋:** ① 남은 수정을 날리지 않는다. ② 새 브랜치는 **원격의 최신** 기본 브랜치 위에 판다(내 컴퓨터의 옛 main이 아니라). ③ 브랜치를 만드는 것까지만 한다 — 지우기 · 커밋 · 푸시는 시킬 때만.

## 1. 남은 것이 없는지 본다

- `git status` — **커밋하지 않은 파일이 있으면 멈추고 알린다.** 그 파일을 새 작업에 가져갈지, 앞 작업에 커밋할지(ship), 그대로 둘지 사람이 고른다. 임의로 지우거나 숨기지(stash) 않는다.
- 지금 브랜치의 PR 상태를 본다(`gh pr list --head <브랜치> --state all`).
  - **병합됨** → 다음 단계로.
  - **열려 있음** → "앞 PR이 아직 병합 전이에요 — 새 브랜치에는 그 변경이 없어요"라고 알린다. 앞 작업 위에 쌓아야 하면 사람이 말한다.
  - **PR 없음 · 푸시 안 한 커밋 있음** → 그 커밋이 새 브랜치에 안 따라간다고 알린다.

## 2. 최신을 받는다

- `git fetch origin`.
- 그사이 기본 브랜치에 들어온 변경을 **한 줄씩** 보인다 — 누가 · 무엇(병합 커밋 · 버전 기록 줄). 내 PR이 병합된 것도 확인해 알린다.
- 다른 사람의 변경이 내가 하려는 작업과 같은 파일을 건드렸으면 짚어 준다(나중에 부딪칠 자리).

## 3. 새 브랜치를 판다

- 이름은 **프로젝트 규칙**을 따른다(CLAUDE.md · git 규칙 문서 · 지금까지의 브랜치 이름에서 모양을 본다. 예: `v2/<주제>_<이니셜>`, 이슈 키가 있으면 넣기). 주제를 말하지 않았으면 한 가지만 묻는다: "무슨 작업인가요?"
- 원격 기본 브랜치에서 바로 판다: `git switch -c <새 브랜치> origin/main`. 따라가기 표시(upstream)는 풀어 둔다(`git branch --unset-upstream`) — 첫 푸시 때 제 이름으로 잡힌다.
- 같은 이름이 이미 있으면 덮어쓰지 않고 다른 이름을 제안한다.

## 4. 알린다

- 새 브랜치 이름 · 바탕 커밋(짧은 번호), 고친 것 없이 깨끗한지.
- 2에서 본 새 변경 요약(있으면).
- 다음에 할 말 안내 한 줄 — 예: "고칠 곳을 [문제] · [원인] · [출력]으로 주시거나 화면을 찍어 보내 주세요."

## 시키면 같이 하는 것

| 말 | 하는 일 |
|---|---|
| "병합된 브랜치 지워줘" | 지우기 전에 `git log origin/main..<브랜치>`가 비었는지 본다(안 올라간 커밋이 없어야). 내 컴퓨터 쪽만 지우고, 원격 브랜치는 따로 묻는다 |
| "앱 실행해줘" · "서버 켜줘" | 새 바탕 코드로 다시 켠다(켜져 있던 것은 끄고). 켜졌는지 응답으로 확인한다 |
| "설치도 해줘" | 바탕 코드에서 의존성이 바뀌었으면(package.json 등) 설치 명령을 돌린다 |

## 하지 않는 것

- `git reset --hard` · `git clean -f` · `git checkout -- <파일>` · 강제 푸시.
- 기본 브랜치(main) 위에서 바로 작업을 시작하는 것.
