# PRD → TASK — 요구를 작업으로

**약속 넷:** ① PRD에 없는 요구를 만들지 않는다 — 빠진 것이 보이면 TASK에 넣지 말고 PRD에 보완을 제안한다. ② 숫자 · 파일 수 · 줄 수는 PRD에서 베끼지 않고 **그 자리에서 다시 센다.** ③ 빼거나 옮기자는 작업은 **누가 넣었는지(`git log -S`)** 먼저 본다 — 남의 결정이면 그 사람 몫으로. ④ 코드는 고치지 않는다. TASK 파일 하나(와 PRD의 링크 한 줄)만 만든다.

## 0. 들어온 것을 본다

- PRD 경로를 받는다. 없으면 한 가지만 묻는다: "어느 PRD인가요?"
- PRD를 **끝까지** 읽는다. 아래 네 절이 있어야 옮길 수 있다 — 없으면 멈추고 PRD에 그 절을 채우자고 말한다(TASK로 메우지 않는다).

| PRD에 있어야 하는 것 | TASK의 어디로 가나 |
|---|---|
| 요구 — 번호 · EARS 문장 · **끝 조건** · 코드 자리 | 2절 작업 표(요구 칸 · 끝 조건 칸) |
| 만드는 차례 — PR 나눔 · 왜 그 차례 · 고치는 파일 | 1절 PR 범위 계약 |
| 정할 것 — 무엇 · 선택지 · 권함 · 누가 | 3절 정할 것 ↔ 작업 |
| 시험 — 요구 ↔ Given-When-Then · 걸리는 기존 시험 | 2절 **시험** 작업 · 4절 공통 |

- 프로젝트에 앞선 TASK가 있으면 그 틀을 그대로 따른다(이름 · 절 번호 · 표 머리). 같은 저장소의 두 TASK가 다른 모양이면 읽는 사람이 둘을 익힌다.
- 프로젝트 규칙 문서(CLAUDE.md · 코드 규칙 · git 규칙)에서 **커밋 전 검사 명령 · PR 기록 방식(변경 조각 등) · 담당 폴더**를 찾아 둔다 — 4절 공통에 들어간다.

## 1. 재고 확인한다 — 쓰기 전에

- **코드 자리:** PRD가 적은 함수 · class · 파일이 지금 코드에 있는지 `grep`으로 본다. 줄 번호는 밀리니 TASK에는 **이름**으로 적는다.
- **숫자:** PRD의 "n곳 · n개"는 다시 센다. 다르면 TASK에 **잰 값과 날짜**를 적고 PRD 값이 어디서 왔는지 한 줄 덧붙인다.
- **빼는 것의 출처:** 지우거나 옮기는 작업마다 `git log --format='%h %ad %an — %s' --date=short -S'<글자>' -- <파일>`로 처음 넣은 커밋 · 사람을 본다. 요구서에 그 사람의 결정으로 적혀 있으면 "그 결정을 바꾸는 일"이라고 3절에 올린다.
- **결정과 어긋나는 곳:** 최근 결정(결정 모음 · 시험 주석 · PRD의 "정함" 줄)과 PRD 그림 · 글이 다른 데가 있으면 TASK에 넣지 말고 PRD 쪽에 먼저 짚는다.

## 2. TASK를 쓴다

파일: PRD와 같은 폴더, 같은 날짜 · 이름에 `-TASK.md`(예: `2026-10-30-퀘스트-탭-합치기-TASK.md`). 맨 위에 `<!-- claude-drafted: YYYY-MM-DD — 누구 요청, 바탕 PRD -->`.

**한 줄로:** 요구 n개를 PR m개 · 작업 k개로 쪼갰다. 시험이 구현 앞. 무엇이 바뀌지 않는지(서버 · 데이터 등) 한 마디.

### 0절 지금 상태

표 하나 — 기준 커밋 · 요구 번호 상태((안)인지 올랐는지) · 이미 정한 것(누가 · 날짜) · 결정 대기(누가) · **기한**(기능 동결 · 알려진 실패 기한 등 코드에 영향 주는 날짜) · "줄 번호는 이름으로 적었다".

### 1절 PR 범위 계약

| PR | 브랜치(예시) | 무엇(요구 번호) | 고쳐도 되는 파일 | **건드리면 안 되는 파일** | 되돌리기 | 사람 확인이 필요한 일 |

- PR 차례의 **이유**를 한 줄로(같은 파일을 고쳐서 / 다른 파일이라 병렬 가능 **[P]**).
- 끝나면 `git diff --stat`로 범위 안인지 본다는 줄.
- 프로젝트의 PR 기록 규칙(변경 조각 · 담당 알림 · 앱 버전 안 건드림)을 그대로 옮긴다.

### 2절 작업 목록

PR마다 표: `| # | 작업 | 요구 | 의존 | 끝 조건 |`. 번호는 T01부터 문서 전체에서 이어진다.

- **시험 작업이 구현 작업 앞에 온다.** 시험 줄의 끝 조건은 "지금은 실패(이유)" — 실패를 먼저 보는 것이 목적이다.
- 구현 작업은 **함수 · class · 조각 이름**으로 어디를 어떻게 바꾸는지. 끝 조건은 "T0n 통과" 또는 grep으로 셀 수 있는 것(`.book` 0 · 갈색 0곳).
- 결정이 안 난 것에 걸리는 작업은 **기본값**을 적고 "결정이 오면 문구 하나만" — 결정 때문에 작업이 멈추지 않게.
- PR마다 마지막에 **기존 시험 고침 + 사진 · 잰 값** 작업 하나. PRD 11절(확인 못 한 것)의 줄을 "확인함"으로 바꾸는 것이 그 작업의 끝 조건이다.
- 알려진 실패 목록 · skip된 시험이 이 화면을 찾으면 그것을 **살리고 빼는 작업**을 넣는다 — 통과하는 시험이 목록에 남으면 다시 깨져도 막히지 않는다.
- 조사가 필요한 것(PRD가 "못 찾았다"고 적은 것)은 그 PR의 **첫 작업**으로 "조사"를 둔다.

### 3절 정할 것 ↔ 작업

| PRD 9절 # | 무엇 | 막는 작업 | 기본값(결정 전) | 상태 |

- PRD의 정할 것 번호를 **그대로** 쓴다(새 번호를 매기지 않는다 — 두 문서가 같은 번호여야 찾는다).
- **전체를 막는 결정**(언제 만드나 등)은 기본값이 없다고 적고 맨 위에 둔다.
- 이미 정한 것은 "**정함**(누가 날짜 '한 말')"로. 누구 결정인지 확인한 것은 커밋 번호와 함께.

### 4절 공통

커밋 전 검사 명령 · 링크 검사 · 빌드(조각 → 묶기) 명령 · 사진 크기 · "확인함은 실제로 띄워 본 것만" · 색 대비는 검사로 · 요구 ↔ 시험 표의 원천은 PRD.

### 5절 출처

PRD(절 번호까지) · 앞선 TASK(틀) · 규칙 문서 · 기한의 출처.

## 3. 끝내기

- PRD의 "먼저 할 것" 절에 TASK 링크 한 줄을 더한다(PRD 본문은 그 밖에 고치지 않는다).
- 프로젝트의 링크 검사를 돌린다. `[단추 이름](설명)` 모양은 링크로 읽히니 `[단추 이름] — 설명`으로 쓴다.
- **보고는 짧게:** 파일 경로 · 작업 수 · PR 수, 쓰면서 바로잡은 것(다시 센 숫자 · 출처 확인), 결정 대기 중 **전체를 막는 것 하나**, 커밋은 시킬 때만.

## 결정을 물을 때 — 네 줄로

정할 것을 사람에게 물어야 하면 번호만 나열하지 않는다. 항목마다:

1. **무엇을 묻는 건지** — 화면 · 코드에서 어디 이야기인지, 모르는 말은 풀어서.
2. **왜 지금 정해야 하는지** — 어느 작업이 막히나.
3. **선택지** — 둘 · 셋, 각각 하면 어떻게 되나 한 줄.
4. **권함과 이유** — 하나만, 이유는 프로젝트가 이미 정한 원칙을 들어서.

마지막에 표로 다시 묶는다. "권함대로"라고만 묻는 것은 사람이 이미 그 넷을 들은 뒤에만.

## 하지 않는 것

- PRD에 없는 요구를 TASK에 끼워 넣는 것, PRD 본문을 고치는 것(링크 한 줄 빼고).
- 숫자를 베끼는 것, 출처 확인 없이 "뺀다"를 쓰는 것.
- 코드 · 시험 파일을 만드는 것 — 그것은 TASK의 T01부터 할 일이다.
- 서브에이전트를 부르는 것(1인 프로젝트).
