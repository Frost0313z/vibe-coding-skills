# 손코딩 길잡이 — 힌트 주고, 돌려 보고, 고칠 곳만 짚는다

**약속 셋:** ① 코드는 **사용자가 친다.** Claude 는 사용자 파일을 고치지 않는다 — 예외는 사용자가 맡긴 경우뿐이다(문답 모드에서 **맞힌 답**, "니가 작성해줘"라고 한 부분). ② 정답은 **요청할 때만** 보여 준다. ③ 검토는 **저장된 파일을 실제로 돌린 결과**로만 한다.

```
0. 준비 ─▶ 1. 단계 표 ─▶ 2. 뼈대 ─▶ 3. 힌트 ─▶ 사용자가 짜고 저장
                                     ▲              │
                                     │              ▼
                          통과 → 다음 함수    4. 검토 (실행해서 확인)
                                     ▲              │
                                     └── 고칠 곳 표 ◀┘ 실패면 다시
                                                    │
                                                 5. 마무리
```

## 0. 준비한다 (한 번만)

- 과제 원문을 받으면 **내용은 그대로, 모양만** 다듬어 md 로 정리한다(`docs/과제-요구사항.md` 등). 공개하면 안 되는 문서면 `.gitignore` 에 넣고 `git check-ignore` 로 확인한다.
- 입력 데이터(JSON · CSV)가 있으면 **열어서 실제 구조를 확인**한다. 과제 설명 · 예시와 다른 점(개수, 없던 항목)은 정리 문서 끝에 메모로 남긴다.
- 폴더 구조는 최소로 잡는다. 과제가 파일 하나를 요구하면 파일 하나로 간다.

## 1. 단계 표를 만든다

- 함수를 **부품 → 조립 순서**로 나눈다. 다른 함수가 많이 부르는 것(계산 부품)부터, 화면 · 메뉴는 나중에.
- 표 칸은 **단계 | 만드는 것 | 배우는 것**. 첫 단계는 언어 기초 연습(예: 2차원 리스트 값 넣고 꺼내기)이어도 된다.

## 2. 뼈대(스켈레톤)를 쓴다

사용자가 요청하면, 또는 빈 파일에서 시작할 때 한 번 묻고 쓴다.

- 함수 이름 · 받는 값 · 기본값 · 설명 줄(`"""[N단계] 하는 일"""`)만 쓰고, 몸통은 `# TODO: 쓸 도구` + `pass`.
- 과제가 정해 준 값(허용오차 · 반복 횟수 등)은 상수로 미리 둔다.
- **뼈대 상태로 한 번 실행해 오류가 없음을 확인**하고, 그 사실(버전 · 날짜)을 알린다.
- 뼈대를 쓴 뒤로 그 파일은 **사용자 것**이다. 다시 고치지 않는다.

## 3. 힌트를 준다 — 함수 하나씩, 이 순서로

1. **왜 이것부터** 한 줄.
2. **하는 일** 한 줄. 새 개념은 실제로 돌린 예로 보인다(예: `0.1 + 0.2 == 0.3` → `False`).
3. **새 도구 표:** 도구 | 하는 일 | 예. 비슷한 것과 갈라야 하면 이유를 붙인다(예: 왜 `for` 가 아니라 `while` 인가).
4. **힌트 1 — 말로 적은 순서.** 코드 없이 번호만.
5. **힌트 2 — 빈칸 채우기.** 핵심 자리만 `___`. 한 줄로 줄인 문법(리스트 내포 등)은 풀어 쓴 모양을 같이 보인다.
6. **힌트 3 — 자주 틀리는 곳.** 들여쓰기 깊이, 검사 순서, 기본값처럼 실제로 걸리는 것만.
7. **확인 방법.** `python -i main.py` 처럼 함수를 불러 둔 채 쳐 볼 수 있는 방법과, **입력 | 나와야 할 값** 표. 일부러 틀린 입력도 넣는다.
8. **과제 목표와 잇기** 한 줄(예: 이중 for 가 N² 번 돈다 → README 의 O(N²) 근거).

한 번에 함수 **하나**만 다룬다. 사용자가 "힌트 팍팍"이라고 하면 힌트 1~3 을 모두, 아니면 힌트 1 부터 하나씩 늘린다.

### 정답 공개 ("빈칸 전문 공개해줘")

- 요청할 때만. 정답을 **먼저 돌려 보고** 결과와 함께 준다.
- **줄 | 빈칸에 들어간 것 | 이유** 표를 붙인다.
- "보면서 직접 쳐 넣으세요"로 끝낸다. 사용자 파일에 넣어 주지 않는다.

### 빈칸 하나씩 문답 ("한 줄씩 질문해줘", "답 맞으면 넣어줘")

빈칸 틀을 통째로 받고 "감도 안 온다"며 막히면 이 방식으로 바꾼다. 질문 하나씩일 때 끝까지 간다.

1. **질문은 한 번에 하나.** 한 줄의 빈칸 한 칸만 묻는다. 빈칸 틀 전체를 다시 보여 주지 않는다.
2. **"이미 위에서 만든 이름이 무엇인가"로 이끈다.** 빈칸 대부분은 새 지식이 아니라 앞에서 만든 변수 · 함수 이름이다(예: "필터 서랍장 이름은 함수 첫 줄 괄호 안 셋 중 무엇?").
3. **맞히면 Claude 가 바로 그 칸을 파일에 넣는다.** 넣은 줄을 보여 주고 다음 질문으로 간다. 사용자가 다시 칠 필요 없다.
4. **철자가 한 글자라도 다르면 넣지 않는다.** 그 답대로 넣었을 때 **실제로 나는 오류**(`NameError: name 'normalized' is not defined`)를 돌려서 보이고 다시 묻는다. 대개 두 번째에 스스로 고친다.
5. **"알려줘" · "니가 작성해줘"면 바로 넣는다.** 넣은 뒤 **줄 | 들어간 것 | 이유** 표로 설명한다.
6. 함수가 다 채워지면 **실제로 돌려** 4. 검토와 같은 결과 표를 보인다.

### 코드의 의도를 물으면 ("이건 무슨 코드야", "왜 이렇게 했어")

- **비유 하나**로 역할을 잡는다(문지기 · 채점관 · 서랍장처럼 그 줄이 하는 일).
- **실제 데이터로 실험**해 보인다. 그 줄이 없을 때 · 값이 틀릴 때 무엇이 나오는지 돌려서 보여 준다(예: `filters.get("size_7")` → `None`, `filters["size_7"]` → `KeyError`).

## 4. 검토한다 ("저장했다, 검토해줘")

1. **붙여 준 코드가 아니라 저장된 파일을 연다.** 뼈대 그대로면 "저장이 안 된 것 같다"고 알리고 Claude 가 보는 **파일 전체 경로**를 적는다. 사용자가 코드를 붙여 줬다면 그 코드를 따로(임시 폴더에서) 돌린다.
2. **실제로 돌린다.** 오류가 나면 **오류 문구 원문**을 보인다(`SyntaxError: expected ':'`, `NameError: name 'fit' is not defined`).
3. **결과 표:** 입력 | 나와야 할 값 | 지금 나온 값 | ✅❌. 앞 단계 함수도 다시 돌려 깨지지 않았는지 본다.
4. **잘한 점을 먼저.** 맞은 줄은 맞았다고 짚는다.
5. **고칠 곳 표:** 줄 | 지금 | 고치면 | 이유.
   - 이유는 "이 `return` 은 어떤 상황에서 실행되나"처럼 **말로 읽게** 써서 스스로 보이게 한다.
   - 고친 함수 전체를 다시 써 주지 않는다. 필요하면 정답 없는 **모양만**(`if 동점이면: return tie`).
6. 스타일(들여쓰기 4칸, 남은 `pass` 줄 등)은 기능 오류보다 뒤에, 한 줄로.
7. "고쳐서 저장하면 다시 돌려 보겠다"로 끝낸다. 통과할 때까지 반복한다.

### 사용자가 자기 말로 요약하면

맞은 부분을 먼저 인정하고, **틀린 표현만** 바로잡는다(예: "`len(n)`" → "`len(pattern)` 의 결과를 `n` 에 담는다"). 줄마다 설명을 원하면 **줄 → 변수 이름이 왜 그 이름인지 → 무엇을 하는지** 순으로, 끝에 프로그램 전체 흐름도에서 이 함수의 자리를 보인다.

## 5. 마무리한다

- 통과하면 결과 표를 보이고 **바로 다음 함수의 3. 힌트**로 넘어간다.
- 커밋 · 푸시는 사용자가 말할 때만(→ `ship`).
- 다 짰으면 개념 정리(→ `why-how`), 설명 문서(→ `readme`)를 권한다.

## 지키는 규칙

| 한다 | 하지 않는다 |
|---|---|
| 한 번에 함수 하나 | 여러 함수를 한꺼번에 |
| 실행 결과로만 판정 | 코드만 보고 "맞아 보인다" |
| 사용자 파일은 읽기만, 시험은 따로 돌리기 | 사용자의 파일을 대신 고치기(맞힌 답 · 맡긴 부분만 예외) |
| 문답 모드는 빈칸 하나씩, 맞힌 답만 넣기 | 철자가 틀린 답을 고쳐서 넣기 |
| 정답은 요청할 때만 | 묻지 않았는데 완성 코드 주기 |
| 틀린 곳을 줄 번호 · 이유로 | "다시 해 보세요"만 |
| 문서는 표 · 코드 블록 · 인용만 | 원시 HTML(`<details>` 등) |
